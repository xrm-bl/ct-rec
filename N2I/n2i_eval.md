# n2i_eval_all.py 使い方（条件の評価）

投影へのフィルタ、再構成フィルタ、分割数のどの組み合わせが Noise2Inverse（N2I）に適しているかを、1 つのデータで一括して調べるスクリプト。計算（フィルタ、分割再構成、学習、推論）から分析（ノイズと分解能の数値、グラフ、レポート）までを 1 回の実行で行う。N2I が動く計算機であれば、`raw` のあるディレクトリで実行するだけでよい。

どの条件が良いかは試料や測定条件によって変わる。このスクリプトの結果は、その 1 つのデータについての比較である。

## 何を調べるか

既定では、次の 48 通りの組み合わせを調べる。

| 項目 | 既定値 | 内容 |
|---|---|---|
| メディアンフィルタ | 1、3、5 | a.his の各投影にかける（1 はかけない） |
| ガウシアンフィルタ | σ = 0、0.5、1.0、2.0 | メディアンのあとにかける（0 はかけない） |
| 再構成 | `his_srec_g_c_n2i`、`his_srec_g_r_n2i` | 再構成フィルタの違い（`_c`：Chesler、`_r`：Ramachandran（HAN）） |
| 分割数 K | 2、4 | 投影を角度順に交互に分ける数 |

ケースの名前は `m<メディアン>_g<σ>_<再構成>_K<分割数>` になる（例：`m3_g1.0_c_K4`）。

## 前提

- N2I の環境（n2i_v4.py と Python）が入っていること。インストールは [n2i_v4_usage.md](n2i_v4_usage.md) を参照。
- [ct-rec](https://github.com/xrm-bl/ct-rec) の次のプログラムに PATH が通っていること。ジョブとして実行する計算機では、計算ノードから見える必要がある。
  - `his_mgf`（投影へのフィルタ）
  - `his_srec_g_c_n2i`、`his_srec_g_r_n2i`（分割再構成）
  - `his_rec_g_c`（基準画像の作成）
- データのディレクトリに `raw`（`a.his`、`conv.bat`、`output.log`）があること。
- 画素サイズ（Dr）と回転軸位置（Rc）がわかっていること。回転軸位置は、[N2I_install.md](N2I_install.md) の手順 1 で決める。

## 実行

`raw` のあるディレクトリで、N2I の環境の Python を使って実行する。

```bash
# ポータブル版
~/data/ct-rec/ct-rec/N2I/n2i_portable/python/bin/python3 n2i_eval_all.py

# Ubuntu（setup_n2i.sh でインストールした場合）
~/n2i/venv/bin/python n2i_eval_all.py
```

```
rem Windows
C:\n2i\venv\Scripts\python.exe n2i_eval_all.py
```

n2i_v4.py とそれを動かす Python は、実行に使った Python のインストール先などから自動で探す。見つからない場合は `--n2i` で、ランチャー・n2i_v4.py・インストール先のどれかを指定する。

**画素サイズと回転軸位置**：指定しないと、`pixel size Dr (um):` と `rotation centre Rc (pixels):` を順に聞かれる。オプションで指定する場合は `--dr 1.0 --rc 1018.5` のようにする。面内回転角は `--ra0` で指定でき、既定は 0.0。

**長時間の実行**：全体で数時間かかるので、接続が切れても止まらない形で実行する。この場合はキーボードから入力できないので、`--dr` と `--rc` を必ず指定する。

```bash
nohup ~/n2i/venv/bin/python n2i_eval_all.py --dr 1.0 --rc 1018.5 > n2i_eval_run.txt 2>&1 &
tail -f n2i_eval/eval.log        # 進み具合の確認
```

**最初に試す**：`--dry-run` を付けると、何も実行せずにコマンドの一覧だけを表示する。続けて 1 ケースだけで動作を確かめてから、全体を実行するとよい。1 ケース目は処理済みとして、全体の実行時に飛ばされる。

```bash
~/n2i/venv/bin/python n2i_eval_all.py --dr 1.0 --rc 1018.5 --medians 1 --sigmas 0 --progs his_srec_g_c_n2i --splits 2
```

## 処理の流れ

1. **フィルタ**：`his_mgf` で a.his にメディアンとガウシアンをかけ、組み合わせごとの his を作る（既定で 12 個）。`conv.bat` と `output.log` もそれぞれにコピーする。
2. **分割再構成**：各 his を、再構成プログラムと分割数ごとに再構成する（`<プログラム> <raw> Dr Rc RA0 rec K`）。
3. **学習と推論**：ケースごとに n2i_v4.py の既定の設定で学習し、中央の 1 スライスだけを推論する。
4. **まとめと分析**：中央スライスを集めたスタックを作り、ノイズと分解能を分析してレポートを書き出す。

GPU が複数ある場合は、`--gpus 0,1` でケースを 1 つずつ各 GPU に割り当てて並行処理する。番号は、その実行で見えている GPU（ジョブスケジューラが割り当てた GPU）の中での順番。指定しなければ、環境で決まっている GPU で 1 ケースずつ処理する。

## 出力

```
n2i_eval\
  params.json               使った Dr・Rc・RA0 の記録
  eval.log                  全体の進行記録
  his\m3_g1.0\raw\          フィルタ済みの a.his、conv.bat、output.log
  cases\m3_g1.0_c_K4\       rec\0〜3、training\、infer_check\、denoised\、n2i.log、recon.log
  summary\
    analysis_report.html    レポート（ブラウザで開く）
    analysis_metrics.csv    全ケースの指標
    transfer_curves.csv     周波数ごとの信号の伝達
    summary_center_slice.tif、summary.csv   中央スライスのスタックと、その並び順
    reference.json、reference_rec.log        基準画像の作成の記録
```

`summary_center_slice.tif` は ImageJ／Fiji でそのまま開ける 32 ビットのスタックで、前半がノイズ除去後、後半がノイズ除去前（分割の単純平均）。各スライスにケース名のラベルが付く。大きなファイルになるので、不要なら `--no-stack` で省く。

## レポートの見方

分析は、中央スライスの一部（既定は中央の 512×512 画素）で行う。分割どうしに共通の成分（試料の構造や再構成固有のパターン）に左右されないよう、**投影を 2 つの独立な半分に分けた像**（K=2 は分割 0 と 1、K=4 は 0+2 と 1+3）を使う。

| 指標（CSV の列名） | 意味 | 見方 |
|---|---|---|
| ノイズ（除去前）（noise_avg） | 2 つの半分の差から求めた、ノイズ除去前の像（分割の平均）のノイズの標準偏差 | 投影フィルタや再構成フィルタでノイズがどう変わるか |
| 取り除いた量（removed） | 「除去前 − 除去後」の標準偏差 | ノイズ（除去前）に近いほど、ノイズの大半を取り除いた |
| ノイズ（除去後・推定）（noise_left） | 除去前のノイズの分散から、取り除いた成分の分散を引いて求めた推定値 | 小さいほど良い。0 は、取り除いた成分がノイズの量を上回った（構造も削った）ことを示す |
| f50（f50_avg、f50_den） | 信号の伝達が 0.5 に落ちる空間周波数（cycles/pixel）。基準ケースの信号に対する比で測る | 大きいほど鮮明。0.5 は、測定範囲内で 0.5 を下回らなかったことを示す |
| 伝達（H02_*、H03_*） | 空間周波数 0.2、0.3 cycles/pixel での信号の伝達 | 1 に近いほど、基準ケースと同じ鮮明さ |
| 取り除いた成分 ÷ ノイズ（rr_low、rr_mid、rr_high、rr_top） | 帯域ごと（低い周波数から順に 4 つ）のパワーの比 | 1 ＝ ちょうどノイズの分だけ除去。1 より大きい ＝ ノイズ以外も除去。小さい ＝ ノイズが残った |
| 共通の高周波成分（common_hf） | 2 つの半分の、高い周波数（0.4〜0.5 cycles/pixel）での相関 | 大きい場合、分割間で共通の高周波成分がある。フーリエリング相関（FRC）による分解能の評価が使えないことを示す |
| 基準との類似度（ssim_ref）、基準とのずれ（bias_ref） | 通常の再構成（基準画像）との比較 | 基準画像もノイズを含むので、正解との一致度ではない。通常の再構成からの変化の大きさの目安 |
| パレート最適（pareto） | 除去後に「より鮮明で、かつノイズも少ない」ケースが他にない条件 | この中から、目的に合う分解能とノイズの兼ね合いのものを選ぶ |

**信号の伝達の基準ケース**は、フィルタなしで分割数が最小のケースのうち、最も鮮明なもの（中〜高周波の信号が最も強いもの）が自動で選ばれ、レポートの冒頭に表示される。

**レポートの構成**

- **要点**：フィルタなしの各ケースでの、ノイズと f50 の変化。パレート最適なケースの一覧。
- **残ったノイズと分解能**：横軸 f50、縦軸ノイズの散布図（分割数ごと）。白抜きが除去前、塗りつぶしが除去後で、同じケースを線で結んでいる。右下ほど良い条件。
- **信号の伝達**：フィルタなしのケースの、周波数ごとの伝達の曲線。
- **画像**：除去前、除去後、取り除いた成分。取り除いた成分に試料の輪郭が見えなければ、構造を削っていない。
- **全ケースの表**：パレート最適の行に色が付く。

## 基準画像

通常の再構成との比較には、中央スライスを通常どおり再構成した画像（例：`raw/rec00118.tif`）を使う。分析の開始時に、`raw` のディレクトリで次のコマンドを自動で実行して作る。回転軸位置、画素サイズ、面内回転角は、分割再構成と同じ値を使う。

```
his_rec_g_c <中央スライスの番号> <Rc> <Dr> <RA0>
```

- このスクリプトが同じ値で作った記録（`summary/reference.json`）がある場合は、作り直さずに使う。
- 記録のないファイルが既にある場合は、`rec00118.before_n2i_eval.tif` のように名前を変えて残し、作り直す。
- 既存のファイルをそのまま使いたい場合は `--ref raw/rec00118.tif` で指定する。自動で作らせない場合は `--no-ref-rec` を付ける。
- 基準画像は `his_rec_g_c`（Chesler フィルタ）による 1 種類なので、再構成フィルタの違うケースは、それだけで基準との差が大きく出る。基準との比較は、同じ再構成フィルタの中で行う。

## 中断と再開

各段階（フィルタ、再構成、学習、推論）が正常に終わるたびに印のファイル（`.done_filter` など）を残すので、止まっても同じコマンドで再実行すれば、終わった段階を飛ばして続きから処理する。

| 中断した段階 | 再開時の動作 |
|---|---|
| フィルタの途中 | そのフィルタをやり直す |
| 再構成の途中 | 書きかけの `rec` を削除して、そのケースの再構成をやり直す |
| 学習の途中 | そのケースの学習を最初からやり直す |
| 推論の途中 | 推論をやり直す |

- **値の確認**：再開時に Dr・Rc・RA0 が前回（`params.json`）と違うと、処理を始めずに止まる。値を変えてやり直す場合は、`--out` で別のディレクトリを指定するか、出力ディレクトリを削除する。
- **失敗したケース**：あるケースが失敗しても残りは続け、最後に失敗したケースを表示する（終了コードは 1）。原因を直して再実行すれば、失敗したケースだけをやり直す。
- **止め方**：画面で実行している場合は Ctrl+C。`nohup` で実行している場合は、スクリプト本体だけを止めると、実行中の再構成や学習が残ることがある。次のようにまとめて止め、`nvidia-smi` で残っていないことを確認する。

  ```bash
  pkill -f n2i_eval_all.py; pkill -f n2i_v4.py; pkill -f his_srec
  ```
- **条件を変えた再実行**：印は「その段階が終わったこと」だけを記録している。学習のオプションを変えてやり直す場合は、そのケースの `.done_train` と `.done_infer` を削除する。
- **分析だけやり直す**：`--analyze-only` を付ける。分析する領域を変えるとき（`--roi-center`、`--roi-size`）などに使う。

## 主なオプション

| オプション | 既定値 | 内容 |
|---|---|---|
| `--dr`、`--rc` | なし（必須） | 画素サイズ（µm）、回転軸位置。指定しなければ聞かれる |
| `--ra0` | 0.0 | 面内回転角（deg） |
| `--raw` | raw | a.his、conv.bat、output.log のあるディレクトリ |
| `--out` | n2i_eval | 出力ディレクトリ |
| `--medians` | 1 3 5 | メディアンの大きさ |
| `--sigmas` | 0 0.5 1.0 2.0 | ガウシアンの σ |
| `--progs` | his_srec_g_c_n2i his_srec_g_r_n2i | 分割再構成のプログラム |
| `--splits` | 2 4 | 分割数 |
| `--gpus` | なし | 並行して使う GPU（例 `0,1`） |
| `--train-args` | なし | 学習に渡す追加のオプション（例 `"--iters 1000"`） |
| `--infer-args` | なし | 推論に渡す追加のオプション |
| `--infer-half` | 0 | 中央スライスの前後、この枚数まで推論して分析に使う |
| `--roi-size`、`--roi-center` | 512、画像の中心 | 分析する領域の大きさと中心（`y,x`） |
| `--ref`、`--ref-prog`、`--no-ref-rec` | 自動 | 基準画像の指定、作成に使うプログラム、自動で作らない |
| `--delete-rec` | なし | ケースが終わるたびに、中央スライス以外の分割再構成を削除する |
| `--keep-cache` | なし | 学習用キャッシュを残す（既定では学習後に削除） |
| `--no-stack`、`--no-analyze` | なし | まとめのスタック、分析を省く |
| `--summary-only`、`--analyze-only` | なし | まとめと分析だけ、分析だけをやり直す |
| `--n2i` | 自動 | n2i_v4.py、ランチャー、インストール先のいずれか |
| `--dry-run` | なし | コマンドを表示するだけで実行しない |

## 時間とディスクの目安

**時間**：1 ケースは「再構成 ＋ 学習（既定 2000 回）＋ 中央スライスの推論」で、ほとんどが学習の時間。2048×2048 × 237 枚のデータを NVIDIA A100 で処理した例では、1 ケース約 6 分（再構成 0.4 分、学習 5.0 分）、48 ケースで約 5 時間だった。GPU を 2 枚使えば、ほぼ半分になる。

**ディスク**：分割再構成はすべて残すので、容量が大きくなる。

| 項目 | 容量 |
|---|---|
| フィルタ済みの his | 元の a.his × フィルタの組み合わせの数（既定 12） |
| 分割再構成 | 1 ボリューム × 分割数の合計（既定 2 + 4 = 6）× 再構成プログラムの数（2）× フィルタの数（12）＝ 144 ボリューム |
| 学習用キャッシュ | 学習後に削除する |

1 ボリュームは「スライス数 × 高さ × 幅 × 4 バイト」。開始時に、フィルタ済みの his に必要な容量とディスクの空きが表示される。容量が足りない場合は `--delete-rec` を付けると、ケースが終わるたびに中央スライス以外の分割再構成を削除する。

## 注意

- **分析は 1 か所**：中央スライスの 1 つの領域での評価である。別の位置（`--roi-center`）や、前後のスライスを含めた評価（`--infer-half`）でも確かめると確実。
- **除去後のノイズは推定値**：取り除いた成分がノイズだけの場合に正確になる。
- **除去後の f50**：残ったノイズの分だけ、わずかに大きく出る傾向がある。
- **メディアンフィルタ**：非線形なので、メディアンを含む条件の信号の伝達は目安である。
- **分割数**：分析は、投影を対等な 2 つの半分に分けられる偶数の分割数だけが対象（再構成プログラムが対応する分割数は 2 と 4）。
- **フーリエリング相関（FRC）を使わない理由**：分割どうしの FRC は、分割間で共通の高周波成分があると高い周波数で再び上がり、ぼけを反映しなくなる。そのため、このスクリプトでは 2 つの半分の相互スペクトルから信号の伝達を求めている。

## 評価の例

次は、ある試料（2048×2048 × 237 枚、蜂の巣状の構造）の中央部で得られた結果の一部。数値は画像の単位で、条件による違いの現れ方の一例である。

| 条件（2 分割） | ノイズ（除去前 → 除去後） | f50（除去前 → 除去後） |
|---|---|---|
| `_r`・フィルタなし | 2.27 → 約 0.43 | 0.50 以上 → 0.40 |
| `_c`・フィルタなし | 0.87 → 約 0.33 | 0.25 → 0.24 |
| `_r`・ガウシアン σ=1 | 0.36 → 約 0.21 | 0.19 → 0.19 |
| `_r`・ガウシアン σ=2 | 0.13 → 約 0.10 | 0.09 → 0.09 |

この例では、次のことが読み取れた。

- N2I は、分解能をあまり落とさずにノイズを減らした（`_r`・フィルタなしで、ノイズが約 1/5、f50 は 0.40）。
- 投影フィルタで同じ程度までノイズを減らすと、分解能が大きく下がった（σ=1 で f50 が 0.19）。投影フィルタを強くするほど、N2I が取り除ける分は少なくなった。
- `_c` は `_r` に比べて、再構成の段階でノイズが少なく、分解能は低かった。
- 2 分割と 4 分割で分解能は同じで、除去後のノイズは 4 分割のほうが多かった。

別の試料や測定条件では、結果が変わることがある。
